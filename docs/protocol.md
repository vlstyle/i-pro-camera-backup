# カメラとのHTTPやり取り

i-PRO製ネットワークカメラのSDメモリーカード録画を、仕様書に載っている公式CGIで取得する。実機（WV-S1531L、WV-S3530）で確認した内容を含む。

## CGI

出典: i-PRO「ネットワークカメラ 外部インターフェース仕様書」（H.265対応機種向け、第8章 SDメモリーカード録画）。仕様書は配布元の資料のため、このリポジトリには含めない。

| 用途 | リクエスト | 備考 |
|---|---|---|
| 録画ファイルのリスト検索 | `GET /cgi-bin/get_mp4_list?Datafrom=yyyymmddThhmmssZ&Datato=yyyymmddThhmmssZ&Maxmatches=1-100` | すべて省略可。アクセスレベル1。`ch`はマルチセンサカメラ用 |
| 録画ファイルのダウンロード | `GET /cgi-bin/get_mp4_file?FileName=<名前>` | アクセスレベル3。`ch`はマルチセンサカメラ用 |

リスト検索の応答（`text/plain`）は1行1ファイルで、末尾に件数が付く。

```
10000011_20130307111954_A.mp4,20130307T111954Z,20130307T112005Z
...
MP4fileNum=51
```

- 時刻はUTC（末尾`Z`）で、実機では小数秒が付く（例: `20260910T210817.08Z`）
- 件数の行は、仕様書では`MP4fileNum`だが、実機（WV-S1531L、WV-S3530）では`Mp4fileNum`。大文字小文字を区別せずに解釈する
- ファイル名は`{連番}_{yymmddHHMMSS}_{種別}.mp4`。連番は録画ごとに単調増加し、重複排除のキーに使える。`yymmddHHMMSS`は**UTCではなくカメラのローカル時刻（実機ではJST）**で、`start_time`の数秒後を指す（例: ファイル名`260911060820`、`start_time`=`20260910T210817Z`=JST 06:08:17）
- 種別（`_A`）の意味は仕様書に記載がない。実機の出力は今のところ`A`のみ（手持ちの録画の範囲）
- 録画は1ファイル15秒前後の短いクリップ
- 検索結果は、`Datafrom`を省略すると古い順に先頭から`Maxmatches`件が返る。`last_fetch`以降を`Datafrom`に指定して古い順に取得する
- `Maxmatches`は最大100。100件に達したら、最後の`end_time`を新しい`Datafrom`にして再検索する（境界の重複は連番で除外）
- 検索中・ダウンロード中は同時に別の検索/ダウンロードができない（200 OKで本文が`ErrorNo=3`）。そのためカメラ単位の処理は直列にする
- ダウンロードの本文エラーは200 OKで`ErrorNo=2`（再配信中）、`ErrorNo=4`（指定ファイル無し）が返る。ステータスコードだけでは判定できない
- 404: SDカード非対応、503: SDカード「使用しない」/未認識/録画形式がH.264ではない
- 認証はユーザー認証方式の設定（`auth_method`）次第。実機の2台は**Basic認証のみ**で、Digest（`curl --digest`）は401になる
- WV-S1531L、WV-S3530の両方で`get_mp4_list`が使えることを確認済み
- `get_mp4_file`（Basic認証）で15秒前後のクリップが200 OKで取得でき、約7MBのMP4（`ISO Media, MP4 v2`）として保存できることを確認済み。録画1件あたり数MB規模になるため、ストリーミング保存が必要
