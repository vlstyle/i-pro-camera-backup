# このプロダクトで成し遂げること

## 目的

自宅に設置したPanasonic i-PROネットワークカメラ（WV-S1531L、WV-S3530）のSDカード録画を、カメラのHTTPインタフェース経由で定期的に取得し、安全に保管できるようにする。既存のPython+bash実装をGoで再構成し、単一バイナリで運用できる形にする。

## 前提

- 実行するPodはカメラ（LAN内のHTTP）に到達できるネットワークにいること

## 機能の分離

次の2つは目的も実行頻度も失敗の影響も異なるため、**別機能として設計する**。互いのコードに依存せず、ローカルの保存ディレクトリ（レイアウトと完了の規約）だけを契約として連携する。

| | 取り込み（fetch） | 退避（archive） |
|---|---|---|
| 役割 | カメラをクロールし、新しい録画をローカルに保存する | ローカルに溜まった録画を外部ストレージへアップロードし、整理する |
| 頻度 | 高頻度（5分間隔程度） | 低頻度（1時間に1回程度、設定値） |
| 入力 | カメラのHTTP | ローカルの保存ディレクトリ |
| 出力 | ローカルの保存ディレクトリ | AWS S3（将来は他のクラウドストレージも） |
| 失敗時の影響 | 次回の実行で増分を取り直す | 次回の実行で再アップロード。ローカルに残るだけ |

- 人感検知で1時間に何度も録画されるため、1時間に1回の取得では録画ログが1ページに収まらずページ送りが必要になる。取り込みを高頻度にして1回の実行で見る範囲を直近の差分に絞り、ページ送りを避ける（ページ送り自体への対応も堅牢性のため検討する）
- 取り込みは、保存完了前のファイルを退避側が拾わないよう、一時ファイルに書いてからrenameで確定する
- 退避は、アップロード成功を確認してからローカルを削除する（削除の有無は設定値）
- 単一のイメージ・バイナリとし、内部で取り込みと退避を別パッケージに分ける（サブコマンドを併設するかは未決）

## リポジトリの責務

このリポジトリに置くのは**プログラム（ソース、テスト、コンテナイメージのビルド定義）のみ**。K8sのManifest/CronJob/PVC/Secretなど実行環境の定義は別のリポジトリで管理する。

## 実行モデル（決定）

- コンテナイメージとして配布し、**ワンショット実行**（起動し、処理して終了）する。常駐デーモンにはしない
- プログラムが実行環境に求める契約:
  - 書き込み可能な永続ディレクトリ（録画の保存先と実行状態）が1つ与えられる
  - 1回の実行の中で「取り込み → 条件を満たせば退避」を順に行う
  - 設定は環境変数で与えられる
  - 同じディレクトリに対する同時実行は、プログラム側のロックファイルで防ぐ（実行環境側の制御に依存しきらない）
  - カメラのHTTPに到達できるネットワーク上で実行される

### 退避の起動条件

- 永続ディレクトリ上に実行状態（`last_fetch`、`last_archive`など）を保存する
- 実行時に取り込みが終わった後、現在時刻の「時（Hour）」が`last_archive`の時（Hour）より進んでいれば退避を行い、成功したら`last_archive`を更新する
- 退避の対象は、ローカルに保存が確定している録画ファイルすべて（取り込み中の一時ファイルは対象外）
- `last_fetch`の更新と`last_archive`の更新は別々に持つ。退避に失敗しても取り込みは進み、次回の実行で退避を再試行できるようにする
- 退避の間隔（毎時以外にするか）は設定値

## スコープ

### 取り込み（fetch）

- 複数カメラの設定を環境変数から読み込む（ホスト、認証、保存先）
- [protocol.md](protocol.md)の手順による録画ログ取得と動画ダウンロード
- 増分取得（取得済みの録画は再取得しない）。失敗した録画は取得済みにしない
- 録画ログが複数ページにわたる場合はページ送りし、`last_fetch`の時刻までさかのぼって取りこぼしなく取得する（カメラ停止・実行停止後の追い付きも兼ねる）
- ストリーミング保存、一時ファイル経由の原子的な保存
- カメラ単位のエラー分離、タイムアウト・リトライ
- 同時実行しても壊れない排他制御
- 構造化ログ

### 退避（archive）

- 設定した間隔でローカルの録画をS3へアップロード
- アップロード間隔・対象期間・アップロード後のローカル削除の有無は設定値で制御
- 録画ファイル（mp4）を1ファイルずつそのままS3へアップロードする（決定）。zip化はしない。キーは`{プレフィックス}{カメラ名}/{yyyy}/{yyyymm}/{yyyymmdd}/{連番}_{yymmddHHMMSS}_A.mp4`（日付はファイル名のローカル時刻）で、連番により再アップロードしても冪等
- 1ファイルずつにする理由: mp4は圧縮済みでzipの効果がなく、S3のリクエスト料金も月数十円程度で差が出ないため、実装の単純さと1ファイル単位の再試行を優先する
- 圧縮はしない（決定）。実機の録画20本の計測で、gzip/zipとも約20%（22〜24%が中心）縮むことを確認したが、削減はストレージ代で月数ドル規模で、圧縮後は直接再生できなくなるため見送る。保管料はS3のライフサイクル（安価なストレージクラスへの移行）で抑える。必要になれば、退避時にgzipして`.mp4.gz`で置く形で後から追加できる
- S3の認証も環境変数で渡す（AWS SDKの標準の環境変数）

### 対象外（現時点）

- ライブ映像の取得・配信
- カメラ設定の変更
- 動画の再エンコード・解析
- 常駐プロセス（デーモン）化

## 環境変数

カメラ名（`CAMERAS`の要素）は`[a-z0-9_]`のみとし、ローカルの保存先ディレクトリ名とS3のパスに使う。カメラごとの変数名には、カメラ名を大文字にしたものを使う。

| 変数 | 必須 | 既定値 | 内容 |
|---|---|---|---|
| `CAMERAS` | ○ | - | 対象カメラ名のカンマ区切り（例: `camera1,camera2`） |
| `CAMERA_<NAME>_HOST` | ○ | - | カメラのホスト（必要ならポート付き。例: `192.168.1.1`） |
| `CAMERA_<NAME>_USER` | ○ | - | Basic認証のユーザーID |
| `CAMERA_<NAME>_PASSWORD` | ○ | - | Basic認証のパスワード |
| `DATA_DIR` | | `/data` | 録画と実行状態の保存先（永続ディレクトリ） |
| `FETCH_HTTP_TIMEOUT` | | `60s` | カメラへのHTTPリクエストのタイムアウト |
| `FETCH_REQUEST_INTERVAL` | | `1s` | カメラへの連続リクエストの間隔 |
| `ARCHIVE_S3_BUCKET` | | 未設定 | 設定するとS3への退避が有効になる。未設定なら取り込みのみ |
| `ARCHIVE_S3_PREFIX` | | 空 | S3キーの先頭に付けるプレフィックス |
| `ARCHIVE_S3_ENDPOINT` | | 未設定 | S3互換エンドポイントを使う場合のURL |
| `ARCHIVE_INTERVAL` | | `1h` | 退避を行う間隔（時単位の境界で判定） |
| `ARCHIVE_DELETE_LOCAL` | | `true` | アップロード成功後にローカルのファイルを削除する |
| `LOG_LEVEL` | | `info` | `debug`/`info`/`warn`/`error` |
| `LOG_FORMAT` | | `json` | `json`/`text` |

S3の認証とリージョンはAWS SDKの標準の環境変数（`AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY`、`AWS_REGION`など）に従う。

## 決定事項

- 実行形態: コンテナのワンショット実行（実行環境の定義は別リポジトリ）
- 設定: 環境変数でコンテナに投入（命名は「環境変数」を参照）
- ライセンス: MIT
- S3の退避形式: 録画ファイルを1ファイルずつアップロード（zip化しない）
- 取得方式: 公式CGI（`get_mp4_list`/`get_mp4_file`）、Basic認証（2機種で`get_mp4_list`、1機種で`get_mp4_file`の動作を確認済み。Web UI再現は採用しない）
- 録画の増分取得は`last_fetch`までさかのぼって取りこぼさない（公式CGIなら時間範囲指定、Web UI再現ならページ送り）
- 対応機種: 手持ちのWV-S1531L、WV-S3530のみ。動作確認は実機のみ（模擬サーバーは作らない）
